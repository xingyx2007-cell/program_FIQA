# FIQA PHASE 0：实验方案（仅设计，尚未训练）

> 这是 PHASE 0 的历史方案快照。PHASE 1 清洗了 7 条记录并重新固定划分；当前 A/B/C 数量为 **9,226 / 9,226 / 9,227**，以 [SPLIT_PLAN.md](SPLIT_PLAN.md) 为准。下文旧数量仅解释当时的方案，不可用于当前训练。

## 这一阶段要做什么

核对本地图片与评分，固定 A/B/C 三组，阅读赛题文献，提前规定怎样训练、怎样评估。官方 `val/val/` 没有公开评分，只能在最终方案确定后生成提交预测。

## 为什么要做

若一边看考试答案一边改方法，最后的高分不能说明方法面对新图片也有效。固定划分把“练习”和“一次模拟考试”分开。实际训练样本为 27,686 张，不是网页概数 30,000 张；本地数据完整对应，但尚无法确认两者差异的原因。

## 核心原理

模型根据图片预测一个分数。训练时用有标签样本调整参数；在没有参与这次调整的图片上测量预测与人工分数是否一致。赛题最终指标是 `0.5 × SROCC + 0.5 × PLCC`，二者都越大越好。SROCC 比较从低到高的顺序；PLCC 比较分数的线性一致程度。除了两个相关系数，还应记录 MAE（平均绝对误差），帮助发现分数整体偏高或偏低。MAE 只是诊断指标，不替代赛题指标。

## 容易出错的地方

- `train.csv` **无表头**。`image_id`、`quality_score` 是项目后来赋予的列名；图片编号包含前导零和以 `z` 开头的值，必须按字符串处理。
- 相同图片若进入训练组和验证组，验证成绩会虚高。已发现的四组字节完全相同图片被固定在同一组；其中三组评分有差异，说明标签存在少量噪声。
- 没有人物或来源 ID。只靠文件字节不能识别“同一个人的不同照片”，因此当前分组不能保证身份独立。
- 随机切分每次变化，会使模型对比不公平；现在固定随机种子 `20260930` 和 CSV 文件。
- 图片原始分辨率差异大；训练与验证必须采用一致、明确的缩放与归一化策略。增强不能把质量缺陷任意抹掉或制造错误标签。
- 用 C 或官方无标签 `val/` 反复改模型，会污染最终评估。官方 `val/` 禁止用于调参、纠错和逐张手动改分。
- 小批量的相关系数可能不稳定；若分数几乎相同，Pearson 型损失甚至无法可靠计算。须先用简单回归损失建立基线。

## 我需要理解什么

| 术语 | 本项目中的直观含义 |
| --- | --- |
| Tensor（张量） | 类似 NumPy 数组；一张彩色图经处理后可表示为 `3×224×224` 个数，并可放到 GPU 计算。 |
| Batch（批次） | 一次送进模型的多张图片；批大小会影响显存占用。 |
| Epoch（轮） | 把当前训练组完整看过一次。 |
| Loss（损失） | 预测与目标的误差公式；训练希望它变小。它与最终比赛分数不一定完全相同。 |
| Gradient（梯度） | 损失随每个参数变化的方向和幅度。 |
| Backpropagation（反向传播） | 从损失往回计算梯度的过程。 |
| Optimizer（优化器） | 根据梯度更新参数的规则。 |
| Learning Rate（学习率） | 每次更新的步子大小；过大易震荡，过小可能学得很慢。 |
| CNN（卷积神经网络） | 用可学习的小窗口逐层提取图像信息的模型。 |
| Feature（特征） | 模型从图片中提取的数值描述，如模糊、纹理或光照线索。 |
| Backbone（骨干网络） | 模型负责提取图像特征的主体；后接一个输出质量分数的小模块。 |
| Pretrained Model（预训练模型） | 已在其他数据上学过通用图像特征的模型。 |
| Transfer Learning（迁移学习） | 从预训练参数出发，再用本项目的质量评分学习。 |
| Overfitting（过拟合） | 训练图片上很准，换到 B/C 却明显变差，相当于记住了练习题。 |
| Validation（验证） | 用没有参加当前训练的带标签图片检查效果；这里 B 用于开发，C 用于一次最终检查。 |
| Checkpoint（检查点） | 保存的一次模型参数与训练状态，方便复现或恢复。 |
| SROCC / SRCC | Spearman 等级相关：预测排序与人工排序是否一致。 |
| PLCC | Pearson 线性相关：预测分数与人工分数是否呈线性对应。 |
| Ranking Loss（排序损失） | 成对比较图片，惩罚“好图预测比差图更低”的情况。 |
| FLOPs | 一次模型前向计算大致需要的浮点运算量；赛题限 224×224 输入不超过 500M。MACs 是乘加次数，不能未经口径换算就说等于 FLOPs。 |
| Parameters（参数量） | 模型中需要保存和学习的数值个数；赛题上限 5M。 |

## 暂时可以忽略什么

现在无需推导反向传播公式、理解视频 rPPG 的频谱损失，也无需决定最终网络每一层的细节。先弄清楚数据如何对应、B/C 各自承担什么评估角色，以及什么证据能说明一个改动真的有效。正式模型训练、三折训练和官方 `val/` 推理都不属于 PHASE 0。

## 执行计划

### Stage 1：开发与发现问题

只用 **A（9,228 张）训练**，用 **B（9,229 张）验证**。在 B 上看 SROCC、PLCC、MAE、训练与验证损失曲线，以及不同质量分桶的表现。可依据 B 调整学习率、损失、图片处理、训练轮数和是否使用预训练参数。所有尝试记录配置、随机种子、指标和检查点。C 保持封存。

### Stage 2：一次模拟考试

确定配置后，**重新初始化**模型（若采用预训练则从同一预训练权重开始），只用 **A+B（18,457 张）训练**，随后在 **C（9,229 张）只评估一次**。不能把 Stage 1 的模型直接接着训练后宣称是同一公平实验。C 结果用于估计最终泛化能力，不再基于 C 逐项调参。如果 C 暴露重大方案问题，应明确将其转为开发数据，并另找新的独立测试方法，不能继续把 C 称作“未见过的模拟考试”。

### Stage 3：最终模型与官方预测

模型结构、超参数和训练轮数确定以后，再从同一初始化用 **A+B+C（27,686 张）重新训练**。此时已无本地独立验证集，报告应说明这一点。只对官方 `val/val/` 做统一推理并按比赛要求生成 submission；不使用 `val/` 选择模型、修正数据处理或人工修改单张预测。

以上均为后续计划；PHASE 0 没有训练模型或预测官方图片。

## 3-fold Cross Validation 与 A→B→A+B→C

三折交叉验证把数据分三份，做三次独立训练：每次两份训练、一份验证，再汇总三次指标。它能看到模型对不同验证集是否稳定，**均值通常比单次划分的估计更稳定**，但每个配置至少要训练三次；若还要用不同配置反复比较，成本会成倍增加。反复根据三折结果选方案也会产生乐观偏差；在方案固定后只看一次的 C，则更适合作为独立模拟考试。交叉验证本身也不能消除“同一个人的不同照片跨组”的未知风险。

当前 A→B→A+B→C 方案的开发成本较低，而且 C 可以在方案确定后提供一次较干净的独立检查；它的单次数值会比三折均值更受样本划分影响。对目前约 2.77 万张、尚在建立首个轻量基线的项目，建议**先执行三阶段方案**。若 B/C 差异大、模型选择仍不稳，再考虑在训练集上做固定的三折交叉验证，并保留最终独立测试集；不要在 PHASE 0 执行三折训练。

## 候选基线与待验证假设

建议从带预训练权重的 MobileNetV3-Small（轻量 CNN）加单值回归输出开始，损失先用 Huber 或 Charbonnier 这类对异常评分较稳的回归损失。选择 B 上的 `0.5×SROCC + 0.5×PLCC`，同时检查单项指标。多尺度特征、Pearson Loss（鼓励分数线性相关）和 Ranking Loss 留作逐个消融：每次只增一项，与同样的 B 划分和训练预算比较。若改善不能稳定复现或超出 5M/500M 约束，不纳入最终模型。模型复杂度必须以最终**完整推理路径**、224×224×3 输入和赛题规定口径测量，多个模型集成的成本也必须合计。

结构预检查（未训练、`weights=None`）：将 torchvision MobileNetV3-Small 最后一层改成单值输出，在 `1×3×224×224` 随机输入上得到 `1×1` 输出；参数 **1,518,881**，`fvcore` 对支持的算子统计为 **58,626,560**。该工具同时提示未统计 `hardswish`、`hardsigmoid`、部分乘加等算子，所以此数值只是当前简化模型的初步计数，**不是完整推理方案满足 500 MFLOPs 的正式证明**。后续若加入裁剪、多尺度或集成，须重新核算。
